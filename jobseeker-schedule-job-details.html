Developer spec · Job seeker · virtual.jobfairx.com/schedule

Show the job on the schedule page

When a job seeker opens “Schedule your interview”, the page names the job and lists time slots but never says what the job is. This adds a job summary above the time picker — pay, job type and a two-line preview — with the full description one tap away. It applies to desktop and mobile. Everything needed is already in the page’s API response.

03

What changes

  • The job card gains a pay chip, a job-type chip, a two-line preview of the description, and a “View full job details” button.
  • Expanding shows the full, sanitized description inside the same card, above the time picker. The button changes to “Hide job details”.
  • The title and the company line wrap instead of being cut to one line.
  • The separator between company and location changes from “ - ” to “ · ”.
  • Nothing else moves. The schedule card, time slots, button, interview-method line and every later step stay as they are.

04

05

Formatting

Pay chip

Format each amount on its own. Under 1,000: always two decimals ($18.00, $23.50). 1,000 and up: a thousands separator, with two decimals only when there are cents ($55,000, $52,000.50). A range that crosses 1,000 is fine as $950.00–$1,200/mo. Every posting uses a bare $, US and Canada alike.

compensationTypeDisplayExample
1 Range“$low–$high”. Just “$low” when compensationMaximum is null or equals the low end$18.00–$22.00/hr · $23.50/hr
2 Starting amount“From $value”From $20.00/hr
3 Maximum amount“Up to $value”Up to $60,000/yr
4 Exact amount“$value”$23.50/hr
  • Suffix from compensationPeriod: 1 /hr · 2 /day · 3 /wk · 4 /mo · 5 /yr. Any other value, or none: no suffix.
  • No structured pay — compensationType null or 0, or compensationValue null or 0: show the free-text compensation as the chip if it isn’t empty. Otherwise no pay chip.

Job-type chip

Assuming the bitmask in globals is correct (see section 07): 1 Full-time · 2 Part-time · 4 Contract · 8 Contract to hire. One chip per bit set, in that order. Ignore any other bit. No chip when the value is null or 0. Sentence case — the existing code writes “Full-Time”.

Chip style

Match the mock: no icon, 12px semibold text, 3px × 10px padding, fully rounded. The app’s existing Chip component adds an icon and a 2px border, which this design doesn’t have.

06

Behaviour

  • Where it goes. The job card is DefaultContainer in the BuilderRoutes bundle, in the block that renders while registration.step === "". Build it there and keep it inside that condition — DefaultContainer is also used by the resume-builder steps. Do not change JobSummary.
  • Breakpoints. None new. The card sits inside the existing column, so it follows the page’s current behaviour (500px column from md, logo from lg).
  • Collapsed every time that step mounts.
  • The toggle is a real button with aria-expanded, and aria-controls pointing at the description container.
  • Collapsing a long description: if the top of the job card has scrolled off screen, scroll it back into view.
  • Preview is the plain text of the whole sanitized description — paragraphs and list items joined with spaces — clamped to two lines with an ellipsis. It hides while expanded.
  • No description means null, an empty string, or nothing left after sanitizing. Then hide the preview and the button; the card still shows the title, company line and chips.
  • Sanitize jobDescription on the client (for example with DOMPurify). Allow p br strong b em i ul ol li with no attributes. Unwrap any other tag and keep its text. Then remove paragraphs whose text is only whitespace or non-breaking spaces, such as <p><br></p> and <p><strong>&nbsp;</strong></p>. Keep the spaces between words when removing empty inline tags.

07

Notes from the current code

  • Confirm the job-type mapping with the backend before building that chip. The app decodes commitmentType two ways. The globals enum is a bitmask — 1 Full-time, 2 Part-time, 4 Contract, 8 Contract to hire — and JobSummary uses it. The event Preview page in the schedule bundle reads it as a plain list — 1 Full-time, 2 Part-time, 3 Contract, 4 Temporary, 5 Internship. They disagree from 3 up. The example posting is 1, which is Full-time under both.
  • There are two pay formatters; use neither. JobSummary would print “Between $23.5 and $23.5” for this posting (type 1 Range, both ends 23.5). The Preview page would print “$23.5 – $23.5 an hour”. Build one formatter from section 05.
  • The description isn’t read anywhere in the booking flow today. The only page that shows one is the separate event Preview page (#/preview and #/<token>), which puts it into innerHTML with no sanitizing. Don’t copy that pattern — and it is worth checking whether that page is safe as it stands.
  • JobSummary computes job type, pay and location but never uses them. It renders the title, company, date and time as a sidebar at lg and up, and as a one-line “Schedule Interview For … at …” strip below that. It only mounts once a time has been picked.
  • workplaceType is undecoded. This posting sends 5, and nothing in any bundle the page loads labels it, so there’s no workplace chip. “Hybrid” in the mock is part of the job title.
