Notes for the developer

This page is the design reference for the Workable Candidates tab. Everything above the line is the screen as approved; the names, numbers and employers are samples. The build detail (webhook, resume storage, request matching, data fields, acceptance criteria) is in the Workable to JobFairX Resume Handoff brief.

Where it lives
A new entry in the admin's QUICK LINKS list, right after SMS Automations, labelled Workable Candidates. The NEW tag is optional and can come off after the first weeks. Its own page, not a section of Manage Candidates.
Who is listed
Every candidate Workable delivers for Simple Staffing's postings (applied, not recruiter-sourced), one row per application, whichever board they started on. Rows whose application had no resume file stay in the list with Resume shown as None. Default sort newest applied first, 20 per page, Previous / page numbers / Next as elsewhere in the admin.
Columns
Candidate: name and city; the name opens the candidate's detail (contact details, the resume, the Workable profile link, the texts sent, the request). Job · Employer. Interview: the job's interview date. Applied: date and time of the application, in the time zone the admin uses elsewhere. Source: where they came from, from Workable's referrer domain mapped to a name (indeed.com → Indeed, linkedin.com → LinkedIn, monster.com → Monster, ziprecruiter.com → ZipRecruiter, glassdoor.com → Glassdoor, Workable's own board → Workable board; anything else shows the domain). Indeed gets the blue chip, the others grey. Resume: the filename, opening the stored file; None when Workable had no file; Downloading, retry n in amber while the download job is still retrying. Texts: T1, T2, T3 chips from the existing text log, green when delivered, grey when not sent. Requested: date and time of the interview request, linking to it; Not yet until then. Via: Workable on every row.
Applied row and Day
Last 7 days, Last 30 days (default), Last 90 days and This year filter by the day they applied. Day is a single-day filter on the same field and is always visible: picking a day clears the range chips, and picking a chip clears the day. No Custom button, no date range.
Dropdown filters
Job, Employer, Interview (date), Source, Requested (Any / Yes / No), Resume (Any / Yes / No), Country (All / US / CA), plus a search box for name, email or phone. Every stat, the table, By source and By week all count the same filtered rows, so one job or one employer shows its own conversion.
Stats block
Candidates: rows in the current filter, with how many have a resume. Texted: Text 1 delivered. Requested an interview, with the resume-source split (attached from Workable, uploaded, built, skipped; the spec's four values). Request rate: requested ÷ candidates, whole percent. Median time to request: minutes from Text 1 sent to the request. Request followed: share of requests credited to the last text sent before them (T1, T2, T3). The Hide stats / Show stats button collapses the block to bring the list up; remember the state per admin user.
Blue header row
The table header stays fixed at the top of the screen while the list scrolls (position: sticky; top: 0 on the header cells). No element between the table and the page's scroll container may have overflow hidden or auto, or the header will not stick; use overflow: clip where a clip is needed. On this page the header sticks to the top of the viewport; in the admin it sticks under whatever fixed bar the admin has.
By source and By week
By source: candidates, requested and request rate per source for the filtered rows, All = the totals, bar length = the rate. By week: one grey bar of candidates and one blue bar of requests per week, Monday to Sunday, request rate labelled above each; the current week is partial. Both read the same filtered rows as the table.
Not on this page
No Export CSV, no column chooser, no phone layout: the admin is used on desktop only. Scott, 18 Oct 2026.
